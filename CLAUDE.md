## Layout
- `site/` is the only directory uploaded. Generator output, never hand-edited here: `index.html` (the front page, generated by EGPT `scripts/build-frontpage.js egpt-frqtl` from the shared front-page template and EGPT `site-src/frontpage/egpt-frqtl.json`), `DeSciXAppSDK.js`, and `images/` outside `images/share/` (tile stills copied from EGPT `site-src/frontpage/exhibits/`, their one home).
- Authored here, written by nothing else: `site/share.json` and `site/images/share/` (validated by `scripts/lib/share-contract.mjs`).
- Written only by `npm run assemble` (`scripts/assemble-site.mjs`) from the pinned npm packages: `app.html` (STUDIO, with the absolute roster link), `app-assets/*`, the fixed entries under `pub/` and everything they load under `pub/<build>/`. Nothing is copied from FRAQTL; STUDIO's brand links to the front page.
- The front page's `#proof` tiles are the showcase cards of `scenes/roster.json` (read with the pinned `@descix/frqtl-web/registry`), in order, each linking `showcaseHref(roster, card)`; gated by `scripts/test/frontpage.mjs` (static) and `frontpage-tiles.mjs` (browser, after the roster is uploaded).
- `.descix/manifests/site.json` is an explicit include allowlist: a new file under `site/` must be added or the upload silently leaves it out.
- `kb/` (five KBs, one manifest each), `plugin/` (the `frqtl` plugin), `scripts/`: README.md owns their procedures; read it first.
- `scenes/`: the showcase scenes and their roster, uploaded as app media (never in `site/`); `scenes/README.md` owns the procedure.
- Nothing in `site/` uses a root-absolute path: PROD serves under `/prod/egpt-frqtl/site/`, `descix serve` under `/p/egpt-frqtl/`.

## Serve
`descix serve` from this root; open the gateway ROOT `https://localhost:5173/` (the App Shell wrapping the app), never `/p/egpt-frqtl`. Files are read from disk on every request.

## Upload (the ladder)
- A scene addition or edit: `npm run scene-check`, then `node scripts/upload-scenes.mjs --checkout <this checkout>` (media only; no site upload).
- The site (a pin bump, the front page, STUDIO via the npm): commit the assembly (`npm ci && npm run assemble`), then `scripts/ship.sh --checkout <this checkout> --port <n>`: clean tree, npm ci, the assembly equals the commit, `npm test`, the licence file, the served roster equals `scenes/roster.json` and the front page names no card it lacks, the local smoke (`frontpage-tiles.mjs`, `host-view.mjs`), `descix site upload --dry-run` then the upload (the receipt ends `Site uploaded successfully!`), served == built for every published file (`scripts/served-equals-built.mjs`), and the PROD smoke with stills (`scripts/test/studio-smoke.mjs --root https://egpt-frqtl.descix.net/`). A failed confirm may have landed: measure served == built before any retry.
- Beside it: `frontpage-tiles-controls.mjs --port <n>` (its negative detectors fail open on drift) and `node scripts/lib/share-contract.mjs`.
- Share card: `curl -sS -A 'facebookexternalhit/1.1' https://egpt-frqtl.descix.net/` shows this site's `<title>` and `og:image`; the edge caches a share.json MISS for 300 s after the upload that introduces it.
